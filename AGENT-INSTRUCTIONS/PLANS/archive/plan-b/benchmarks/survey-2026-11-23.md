# Closing survey — geometry plan (plan-b) — 2026-11-23

**Plan scope:** what a hit records and which shapes exist — the face side and texture coordinates,
planes, triangles and bounding boxes (`docs/requirements.md` items 7 to 10). Code head `2b4e2b7`.

**Method:** one read-only `ops-scout` per area, ten areas in parallel, then one further read-only
`ops-scout` cross-checking every claim. The orchestrator wrote this note from the saved returns and
fixed nothing. No earlier survey note exists for this plan.

Read-only survey: `git status --porcelain` was empty before and after, and no product file, test,
configuration or permanent document changed.

## Areas surveyed

1. The hit record and its constructor — `src/hittable.rs`, every `HitRecord::new` call.
2. The scene list, its nearest-hit loop and box pre-test — `src/hittable.rs`, `ray_colour`.
3. The sphere — `src/sphere.rs`.
4. The plane — `src/plane.rs`.
5. The triangle — `src/triangle.rs`.
6. The bounding box and its four implementations — `src/aabb.rs` and each `bounding_box`.
7. The shared cross product — `src/vec3.rs` and its call sites.
8. The scene's triangle object and module wiring — `src/main.rs`.
9. All eleven test functions across `src/`.
10. Documentation accuracy — `AGENT-INSTRUCTIONS/LOCAL/project.md:5`, `docs/requirements.md`,
    `README.md`.

## Findings

No defect was found in the rendering behaviour: requirements 7 to 10 hold, the image is correct and
stable, and the code matches the four frozen contracts. The findings below are preferences and
coverage gaps.

| Id | Class | Evidence | What is wrong | Impact | Recommendation |
|---|---|---|---|---|---|
| F1 | Stale/inaccurate documentation | `src/hittable.rs:15` | The comment `Read by the tests only.` sits above `front_face` only, while `point`, `u` and `v` are equally read only by tests and carry no note | A reader can take the comment as scoped to one field | One doc sentence on the struct instead of the label, if the file is touched again |
| F2 | Dead capability | `src/hittable.rs:9` | `Copy` is still derived; nothing copies a record since the list reads it by reference | A capability the shared design removes anyway | No action here: the materials plan owns the derive list and drops `Copy` |
| F3 | Unnecessary robustness (dismissed) | `src/sphere.rs:41` | `v = 0.5 - asin(y)/PI` has no clamp, so a hit within about 1e-16 of a pole could return NaN | Unreachable: the fixed camera never samples a pole row, and the contract fixes the formula | No action |
| F4 | Inconsistent documentation | `src/sphere.rs:9-18` | `Sphere`, its fields and `Sphere::new` have no doc comments while `Plane` and `Triangle` do | Cosmetic inconsistency between sibling shapes | Optional one-line doc comments for parity; pre-dates this plan |
| F5 | Weak test | `src/triangle.rs:80,88-89` | The barycentric test hits `(0.25, 0.25)`, where `u == v`, so swapping the two weights would still pass | A future refactor could swap the weights silently | Move the test ray to an asymmetric point when the test is next touched |
| F6 | Missing coverage | `src/triangle.rs:30-31,41` | The parallel-ray, `v < 0`, `u + v > 1` and back-face paths of the triangle hit have no test | An error in those branches would go unnoticed | Optional single back-face or parallel-ray case if the hit is ever changed |
| F7 | Inaccurate documentation | `src/aabb.rs:20` | The doc says a hit has `t` in `t_min..t_max`, but the code accepts the closed interval, unlike the shapes' strict `t >= t_max` | A reader could misjudge boundary behaviour | Say `t_min..=t_max` if the file is touched again |
| F8 | Duplication (deliberate) | `src/triangle.rs:54-65` | Six inline componentwise min/max calls; `Vec3` has no helper | Readability only, no second code path | No action: a helper would add public API for one caller |
| F9 | Coverage gap | `src/hittable.rs:66-80` | No test proves the list returns the **nearest** hit or narrows with `limit`; a list returning the last hit would pass all eleven tests | The one behaviour the resolution phase changed is unguarded | One test with two shapes on one ray, asserting the near distance; the probe test can cover the `limit` argument |
| F10 | Coverage gap | `src/sphere.rs:45-48`, `src/triangle.rs:53-66` | The sphere's and triangle's reported boxes are never asserted; a box that is too small or built from the wrong corner would silently drop real hits | Requirement 10's per-shape box is unproven at the shape layer | One assertion on a shape's box, or reuse the probe test with a real shape |
| F11 | Missing coverage | `src/aabb.rs:31-32` | The documented zero-direction and NaN-on-face behaviour is never executed: the only test's zero-direction axes pass through the box centre, not a face | The conservative behaviour the comment promises could regress silently | Optional; a ray on a face would cover it |
| F12 | Weak test | `src/rng.rs:29-36` | The reproducibility test only compares two identically seeded generators, so a constant generator passes | The stream's variation and seed dependence are unpinned | Optional, in the materials phase that first consumes the generator |
| F13 | Test cost against the workspace rule | `src/main.rs:95-107` | Both render tests render the full 200 by 100 image and assert one pixel each, while the workspace rule asks for a few pixels of a small image | Milliseconds of cost, adequate assertions | No action; if touched, render smaller |

F9 and F10 are the only findings worth acting on. F3, F8 and F13 need no change.

## Out-of-scope observations

Reported with the evidence already in hand and not investigated further.

- `AGENT-INSTRUCTIONS/LOCAL/project.md:5` names `png.rs` and a command line that do not exist on this
  branch (they exist on plan-c) and omits `material.rs` (on plan-a). The file is shared by every
  worktree and describes the merged product, so it is not this plan's to correct.
- Several public items from the base commit have no doc comment the style guide requires: `Vec3` and
  its methods, `Ray`, `Rng`, `HittableList` and `add`, `Sphere`, `Camera`. None was introduced by this
  plan; its own new items are documented.
- `docs/requirements.md` items 1 and 11 contain a semicolon and a history word (`stays`) the style
  guide forbids, both authored at the base commit. `README.md` departs from the README guide in
  structure and fence tag. Both predate this plan.
- `src/main.rs:1` says the program writes a PPM to standard output, and `main` takes no arguments;
  items 11 to 13 (PNG, command line, progress line) and items 1 to 6 (materials, sampling) are the
  output and materials plans' work.
- The plane rejects an exactly parallel ray with `denominator == 0.0` while the triangle uses a
  `1e-8` epsilon for the same condition. Both are the frozen contracts; the difference is recorded
  only as a consistency question for a later round.
- The fixed scene never constructs a `Plane`, so `Plane::hit` is exercised only by its test.
  Requirement 9 asks that the scene can hold a plane, and the phase froze no plane in the scene.
